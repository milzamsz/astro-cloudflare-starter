# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | ✅ Yes (template)  |

## Reporting a Vulnerability

**Please do NOT report security vulnerabilities through public GitHub issues.**

Instead, report them privately via:

1. **GitHub Security Advisory** (preferred): Security tab → "Report a vulnerability"
2. **Email**: security@[your-domain].com (if configured)

We will acknowledge receipt within 48 hours and provide a status update within 5 business days.

## Security Measures in This Template

This is a static site, so the attack surface is small.

### Content Security Policy
- Hash-based CSP generated by Astro (`security.csp`): every page carries a
  `<meta http-equiv="content-security-policy">` with SHA-256 hashes of the scripts
  and styles it renders — no `'unsafe-inline'` for scripts or `<style>` elements
- Sources live in `src/config/csp.config.ts`; analytics/Umami origins are only
  allowed when configured; Pagefind gets `'wasm-unsafe-eval'`; the contact page
  may frame Google Maps
- Inline style *attributes* are allowed (`style-src-attr`) because Starlight and
  code highlighting set CSS variables that way
- JSON-LD is serialized with `<`, `>` and `&` escaped, so content can't close the
  `<script type="application/ld+json">` element
- `public/_headers` adds HSTS (1 year), the header-only `frame-ancestors 'none'` (clickjacking),
  `object-src 'none'`, `base-uri`, `form-action` and other hardening headers
- Playwright fails CI on any CSP violation

### R2 cleanup function
- The only Pages Function (`functions/api/cleanup.ts`) can modify R2 objects
- `POST` only, guarded by a bearer token (`CLEANUP_SECRET`, at least 32 characters,
  constant-time compare — there is no rate limiting, so shorter secrets are rejected);
  returns 401 without it and 405 for other methods
- Defaults to `dry-run`, and aborts without changes if the build's media manifest
  can't be loaded
- Remove it entirely if you don't use R2

### Privacy
- Analytics (GA4, GTM, Umami) only load when configured
- With `PUBLIC_CONSENT_ENABLED=true`, nothing loads until the visitor accepts the
  consent banner; the choice is stored in `localStorage` (`analytics-consent`)

### Secrets
- All secrets via Cloudflare Pages secrets or `.dev.vars` (gitignored)
- No secrets in code — enforced by `validate:secrets` and trufflehog in CI

### Dependency Security
- **Renovate** weekly grouped updates (patch-level dev tooling automerges when CI is green)
- GitHub Actions pinned to commit SHAs
- **Dependency Review** on every PR (fails on moderate+ severity)
- **Secret scanning** via trufflehog on every pull request, plus `pnpm validate:secrets`

### Infrastructure
- **Cloudflare Pages** — DDoS protection, WAF, automatic TLS

## Scope

This policy applies to:
- The template codebase itself
- Generated projects using this template (adapt to your context)

This policy does NOT cover:
- User-deployed infrastructure (Cloudflare account settings, DNS, etc.)
- Third-party services — report to their security teams
